# ADR-001 … ADR-010 (initial set)

Status: Accepted for rebuild v0.1  
Date: 2026-08-04  
Repository: ClinicalPhysiologyLab

## ADR-001 — Patient Runtime as sole canonical-state authority

**Decision:** All changes to canonical patient state go through `PatientRuntime.dispatch` / `advance` / checkpoint restore.

**Consequence:** UI, scenarios, tests, and future agents share one API. Shared
`Patient` channels are projections and learner inputs; they do not bypass the
runtime.

## ADR-002 — Commands, queries, and observations as separate APIs

**Decision:** Mutating actions are commands; read models are queries; clinical information acquisition is `observe()`.

## ADR-003 — Public physiological ports versus private model parameters

**Decision:** Conditions emit effects on ports such as `vascular.systemicArteriolarTone`. Only model adapters may mention `Rsys`, `V0sv`, `Emax`, etc.

## ADR-004 — Deterministic effect composition with provenance

**Decision:** Each port declares a composition rule. Composition is order-independent unless priority is explicit. Every resolved value retains contribution provenance.

## ADR-005 — Ground truth, observation, and interpretation separation

**Decision:** Latent physiology, observation results, and interpretation labels are distinct types and code paths.

## ADR-006 — Command/event log plus checkpoints for replay

**Decision:** Reproducibility uses fingerprint + seed + accepted command log + periodic checkpoints — not every integrator step.

## ADR-007 — Scenario capability requirements and validation

**Decision:** Scenarios declare required capabilities; runtime initialisation fails clearly when the model set cannot satisfy them.

## ADR-008 — Initial model swap policy

**Decision:** Models are selected at runtime initialisation. Live mid-session swap is deferred.

## ADR-009 — Patient-first UI information architecture

**Decision:** Top-level experience layers are Patient / Examine / Investigate / Treat / Explore. Specialty workspaces remain as Explore lenses during migration.

## ADR-010 — Compatibility adapter strategy

**Decision:** Wrap the current circulation and ECG engines behind versioned adapters. Preserve validated private-parameter targets for complete C5 neurogenic shock (`Rsys` 0.52, `HR` 52, `V0sv` 2900, baroreflex off).

## ADR-011 — Chemistry ground truth separate from laboratory observation

**Decision:** Latent chemistry / haematology state is owned by the Patient Runtime (`ChemistryPublicState`). Haemodynamic consequences (lactate, Hb, urea, BNP, …) are derived into that state unless the learner pins an analyte. `observe.laboratory-panel` measures chemistry into a clinical report; acid–base reading lives in `observations/interpretation/`. The Labs domain is a runtime client — it must not maintain a parallel store, write `Patient` K/Ca as authority, or call `cardio.setParam`. Lessons that change circulating volume use `experimental.circulation-param`.

## ADR-012 — Scenario compiler emits commands and triggers only

**Decision:** Scenario definitions are data. `compileScenario` validates required capabilities (ADR-007) and produces seed `PatientCommand`s plus armed triggers. Triggers may dispatch further commands or emit teaching annotations — they never write private model parameters or bypass `dispatch` / `observe`.

## ADR-013 — Shell information architecture is patient-first

**Decision:** Primary navigation is Patient / Examine / Investigate / Treat / Explore (ADR-009). Specialty simulators mount as Explore lenses. Default landing is the Patient summary; scenarios are started explicitly via `scenario.load`.

## ADR-014 — Runtime stabilization invariants

**Decision:** The runtime owns the authoritative clock (model snapshot `t` / awaited settle). Internal IDs are monotonic and seed-scoped — never `Date.now`/`Math.random`. Checkpoints capture chemistry, channels, interventions, scenario, and timeline. Authority and visibility are enforced at `dispatch`/`query`/`observe`. Venous tone loss raises `V0sv` (pooling). Current Circulation/ECG hosts remain adapter-wrapped behind a model-plugin contract; they are not yet hot-swappable plug-and-play.

## ADR-015 — Platform runtime hardening

**Decision:**
1. `advance()` is `Promise`-based and correlated by `requestId` for live hosts.
2. Checkpoints include `models` (serialized Circulation private state), trigger runner state, chemistry derivations, and fingerprint.scenario. `branch()` remains in-place rewind until isolated runtimes exist.
3. ID factories are instance-local with separate command/observation/checkpoint/event namespaces — no module-global rebind.
4. Authority uses a trusted `RuntimeSession` separate from `command.source`. Empty `mayObserve` denies. Clinical clients use `queryForClient` / observe denial unions; triggers use `internalStateForModels`.
5. Explore cardio sliders, pathology, baroreflex, and lessons dispatch runtime commands.
6. `runtime.reset` clears experimental controls and scenario fingerprint; scenarios declare `initialization: "fresh-patient" | "continue-current-patient"` and may expose `presentationTitle`.

## ADR-016 — Learning layer and learner record

**Decision:** A top-level **Learn** layer (Today / Modules / Review / Record) sits first in the primary rail. It does not change ADR-013: the default landing remains the Patient summary, and Learn announces itself through a due-review badge and the first-run card.

1. **Learner state is not patient state.** The learner record (attempts, spaced-repetition schedule, CME module progress, certificates) lives in `core/learning/`, persists to `localStorage` under a versioned key (`cpl.learner.v1`), and never passes through the Patient Runtime. ADR-014's determinism rules govern the runtime, not the learner record, which is wall-clock by nature.
2. **Items are addressed by stable ids** — `<domain>/case/<id>` and `<domain>/lesson/<id>`. Case and lesson runners register their items with `learning.registry`; the learning layer opens an item through `learning.open(id)`, which the shell implements. No learning code imports a domain.
3. **Options are shuffled on every presentation**, so answer position carries no information.
4. **Confidence is part of the answer.** A case is committed only after the learner states Certain / Fairly sure / Guessing (switchable in Record). Spacing uses SM-2 with a grade built from correctness × confidence; certain-and-wrong is the shortest interval and is surfaced first.
5. **CME modules are data** (`core/learning/modules.js`): objectives, activity refs, parallel pre/post question forms per objective, references, review status and an optional `accreditation` block. Activities count only when done after the module was started. Credit claimed on a certificate is engaged time (page visible, input within 90 s), rounded to ¼ h and capped at the module's designated maximum. Without an `accreditation` block the certificate states that it records participation only.

## ADR-017 — Bedside encounter

**Decision:** Examine opens on a **Bedside** encounter: a stylised, animated patient the learner talks to (menu-driven history), inspects, palpates, auscultates, percusses and instructs (manoeuvres and the full neurological examination), then commits to a diagnosis with a confidence rating.

1. **Findings are derived, not authored.** `bedside/findings.js` is a pure function of the circulation snapshot, chemistry and nervous-system graph. Every finding carries a `basis` string and a `kind`: `model` (read from a modelled quantity), `heuristic` (a bedside rule over modelled quantities where no model exists — respiratory rate, SpO₂, capillary refill, S3/S4) or `case` (authored, e.g. temperature, abdominal tenderness).
2. **Heart sounds are synthesised from the model's last beat** (`bedside/sound.js`): S1/S2 at valve-closure events, murmurs as noise shaped by transvalvular flow. No recordings.
3. **Personas are data** (`bedside/personas.js`): story, history answers, a physiological setup expressed in the lesson vocabulary, key findings for the debrief, and the diagnosis. Encounters with a diagnosis register as `bedside/case/<id>` and join spaced review.
4. The monitor strip is hidden during an encounter until the learner attaches it.
5. **Free-text conversation** through a language model is a planned option; the menu stays as the offline, scorable default.
